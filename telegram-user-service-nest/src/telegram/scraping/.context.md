## 💻 Código-Fonte

### 🔧 **group-scraper.service.ts** (19KB)

Service principal de orquestração.

**Features:**

- Validação de acesso a grupos
- Extração de membros via MTProto
- Cálculo inteligente de delays
- Enfileiramento de transferências
- Estatísticas e progresso
- Retry de falhas

### ⚙️ **transfer.processor.ts** (11KB)

Worker BullMQ com rate limiting.

**Features:**

- Concurrency: 1 (anti-ban)
- Processamento de 2 tipos de jobs
- Tratamento de 6 tipos de erro
- Contador diário por bot
- FloodWait detection e pause
- PEER_FLOOD handling (24h)

### 🌐 **scraper.controller.ts** (2.4KB)

Controller REST com 4 endpoints.

**Endpoints:**

- `POST /scraper/start` - Iniciar scraping
- `GET /scraper/jobs` - Listar jobs
- `GET /scraper/progress/:id` - Status detalhado
- `POST /scraper/retry/:id` - Retentar falhas

### 📦 **telegram-scraping-interfaces.ts** (942B)

Interfaces TypeScript.

**Interfaces:**

- `ScrapeGroupJobData`
- `TransferUserJobData`
- `ScrapingProgress`
- `TransferStats`

### 🔌 **telegram.module.updated.ts** (2.3KB)

Módulo NestJS atualizado.

**Configuração:**

- Registro das 2 filas BullMQ
- Import dos services e processors
- Export das APIs públicas
- Integração com módulos existentes

## 🔒 Segurança e Boas Práticas

### ✅ Sempre Fazer

- Começar com DAILY_LIMIT baixo (20-30)
- Usar contas antigas (> 6 meses)
- Monitorar logs constantemente
- Respeitar FloodWait rigorosamente

### ❌ Nunca Fazer

- Usar contas novas para scraping pesado
- Forçar retry em PEER_FLOOD
- Ignorar erros de FloodWait
- Processar múltiplos jobs simultâneos
